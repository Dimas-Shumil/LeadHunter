# ShumDev Lead Hunter v0.3 — SQLite

Локальная система поиска и оценки организаций для ShumDev: источники, импорт, проверки сайтов, объяснимый Lead Score, CRM и очередь заданий. HTML5 + SCSS + Vanilla JS, Express 5, Prisma 7.10, **SQLite**. Без React, PostgreSQL, Docker и Redis.

## Что работает по исходному коду

- Поиск организаций через OpenStreetMap/Overpass (интернет, ограничение публичного сервиса), адаптеры API 2ГИС и Яндекса (ключи и соответствующие права на использование данных обязательны).
- Импорт CSV/XLSX, нормализация, проверка на дубли, ручные карточки компаний, фильтры и экспорт.
- Задания поиска/импорта/аудита, отдельный worker, прогресс и статусы.
- Техническая проверка сайтов по HTTP; браузерные Lighthouse/Playwright опциональны.
- Lead Score, CRM, заметки, задачи, история действий и OWNER-авторизация.

**Ограничения:** без ключей 2ГИС и Яндекс не заработают; Overpass может быть недоступен или содержать мало организаций; отсутствие сайта в источнике не доказывает его отсутствие в интернете. Код был переведён на SQLite, но реальный старт Prisma с установленными npm-зависимостями ещё НЕ подтверждён в среде подготовки архива (npm-реестр был недоступен). Следующие команды рассчитаны на Windows с доступом к npm.

## Установка на Windows (CMD)

1. Поставьте **Node.js 24 x64**. Никакой SQL-сервер не устанавливается.
2. Распакуйте папку `shumdev-lead-hunter` в `C:\Work\shumdev-lead-hunter`.
3. Выполните:

```bat
cd /d C:\Work\shumdev-lead-hunter
node -v
copy .env.example .env
npm install
npm run db:generate
npm run db:deploy
npm run owner:create
npm run build
npm run dev
```

4. Откройте второе окно CMD:

```bat
cd /d C:\Work\shumdev-lead-hunter
npm run worker
```

5. Откройте **http://localhost:3000** и войдите по созданным OWNER-учётным данным.

**Почему `npm install`, а не `npm ci`?** При конвертации заменён драйвер Prisma (`@prisma/adapter-pg` на `@prisma/adapter-better-sqlite3`). Среда подготовки не имела доступа к npm-реестру, поэтому безопасно сформировать достоверный `package-lock.json` было нельзя; старый lock намеренно удалён. Первый `npm install` скачает зависимости и создаст новый lock. После этого в обычной работе можно использовать `npm ci`.

## Где хранится SQLite

- `.env`: `DATABASE_URL=file:./prisma/dev.db`.
- База: `prisma/dev.db` (создаётся через `npm run db:deploy`).
- Клиент Prisma подключается к ТОМУ ЖЕ файлу через `@prisma/adapter-better-sqlite3`. Prisma Migrate использует относительный `file:./dev.db` (относительно `prisma/schema.prisma`), а runtime — `file:./prisma/dev.db` (от корня проекта); это обходит ошибку Windows OS error 161 при кириллическом пути пользователя.
- `.gitignore` защищает `.env`, `*.db` и журналы SQLite от коммита.
- Копия: `npm run db:backup` (SQLite `VACUUM INTO`, online snapshot; складывается в `prisma/backups/`).

Делайте регулярные резервные копии. Не удаляйте `prisma/dev.db` — это вся база клиентов.

## Автопоиск организаций

Войдите, откройте «Поиск организаций», выберите **Автопоиск**, город **Абакан**, нишу **Грузоперевозки**, лимит **20**. При отсутствии ключей 2ГИС/Яндекс выбирается OpenStreetMap/Overpass. Найденные компании можно увидеть в «База клиентов». Для сетевого поиска нужен интернет; публичный Overpass не гарантирует полноту и может ограничивать запросы.

Настройка источников в `.env`:

- `DGIS_API_KEY` — ключ 2ГИС, дополнительные флаги разрешения сохранения/контактов по договору.
- `YANDEX_MAPS_API_KEY` — ключ Яндекс, отдельное разрешение на накопление данных.
- `OVERPASS_URL` — доступный endpoint.

Не изменяйте `*_STORAGE_ALLOWED` на `true` без необходимых прав. API-ключи не включены в архив.

## Ограничения SQLite

SQLite хорошо подходит для одного локального приложения с одним worker. Параллельная запись ограничена: в код добавлена сериализация конкурентных операций поиска/дедупликации через `_WriteLock` внутри SQL-транзакции и краткие повторы при `SQLITE_BUSY`. Однако при масштабировании на несколько серверов/множество workers следует перейти обратно на серверную БД. Не запускайте несколько workers одновременно.

## Что изменено относительно v0.2/PostgreSQL

- Prisma datasource `sqlite`, SQLite driver adapter, единый путь файла.
- Новая **SQLite-миграция**; старую PG-миграцию не смешивать.
- `pg_advisory_xact_lock` и `FOR UPDATE SKIP LOCKED` заменены SQLite-транзакциями.
- `mode: "insensitive"` удалено из Prisma-фильтров (не поддерживается SQLite); поиск текста через `contains` сохраняется, но Unicode-регистронезависимость может отличаться от PostgreSQL.
- Тестовая БД — отдельный файл `*_test.db`.
- Убраны пакеты `pg` и `@prisma/adapter-pg`.

**Миграция уже существующих данных PostgreSQL не предусмотрена:** версия предназначена для новой установки без локальной базы. При наличии данных в старой БД потребуется отдельная процедура переноса.

Подробнее про тесты, настройки и ограничения: `docs/TESTING.md`, `docs/ARCHITECTURE.md`, `docs/SOURCES.md`.


## Изменения v0.3.6 (октябрь 2026)

Добавлены **Заявки** и **Задачи** в боковую навигацию. Каждая заявка привязана
к организации и имеет канал, сумму, комментарий, статус и историю изменения.
Задачу можно создать из карточки компании либо из раздела «Задачи».

Новая миграция SQLite `20261011120000_inquiries` добавляет таблицу Inquiry;
перед обновлением рекомендуется резервное копирование `npm run db:backup`.

Для проверки известных сайтов аудит анализирует `tel:`-ссылки, Schema.org/JSON-LD
и не более одной страницы «Контакты» на том же домене. Номер считается
найденным, **но не проверенным дозвоном**. Без URL нельзя проверить сайт.
Получение сайта и телефона напрямую из 2ГИС остаётся зависимым от отдельного
разрешения `items.contact_groups`; наличие обычного Places API не гарантирует
доступа к контактам. Яндекс API исключён из активных источников.
